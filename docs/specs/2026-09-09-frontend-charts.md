# usage-hub 0.5.5 前端呈现调整

> 2026-09-09 需求方确认。本轮只改前端呈现（`assets/panel.js` / `assets/panel.css`），
> 不动后端聚合口径、不动接口返回结构、不改数据层。

## 需求来源

1. 单日时「每日 Token 趋势」只有一根柱子，图表区域大片留白；小时消耗趋势应直接沿用
   「每日 Token 趋势」的呈现方式，细节收进点击弹窗。
2. 输入构成卡：昨天/当天按小时，3 天及以上按天。
3. P50/P95 耗时直接从主面板去掉（不看耗时分布），保留「平均每轮耗时」。
4. 刷新按钮旁边的设置齿轮图标偏小。
5. 边界确认：2 天范围（周一时的「本周」）输入构成按小时，即当天+昨天各 24 点。

## 改动清单

### A. 单日 / 多日图表二选一

现状（`renderCharts`）：

- `[data-chart="dailyTokens"]`（每日 Token 趋势）始终显示。
- `[data-chart="dailyHit"]`（每日命中率趋势）在 `days.length >= 3` 时显示。
- `[data-chart="hourly"]`（小时趋势）在 `from === to` 时显示，内含三块：
  token 柱状 + 命中率折线 + 来源类型堆叠。

目标：

- **单日（`from === to`）**：
  - 隐藏「每日 Token 趋势」卡。
  - 显示「小时 Token 趋势」卡（沿用 `[data-chart="hourly"]`），卡片标题由「小时趋势」
    改为「小时 Token 趋势」，卡内**只保留一张 24 点柱状图**，呈现样式与每日趋势一致
    （同一 `barChart` 参数风格）。
  - 命中率折线与来源类型堆叠从卡内移除，改为只在点击放大弹窗里呈现。
- **多日（≥ 2 天）**：
  - 显示「每日 Token 趋势」卡，隐藏小时卡（保持现有行为）。
- **点击放大弹窗**（`openChartModal` 的 `hourly` 分支）：
  - 单日时保留完整信息：小时 Token 柱状图 + 小时命中率折线 + 来源类型堆叠。

验收：

- 单日页面只出现一张趋势图，24 根柱子，不再出现「一根柱子撑一张大图」。
- 多日页面只出现每日趋势图，无小时卡。
- 单日点击小时卡，弹窗同时能看到 token、命中率、来源类型三块内容。

### B. 输入构成粒度切换

现状：`renderCharts` 的 `chCompose` 始终按天（`state.daily`）。

目标：按当前筛选范围天数切换。

- **< 3 天（单日 + 2 天）** → 按小时堆叠。
- **≥ 3 天** → 按天堆叠（保持现状）。

数据来源（纯前端，不改接口）：

- `/api/hourly` **不传 `day`** 时返回筛选范围内所有天的小时序列对象
  `{ "YYYY-MM-DD": [24 个小时对象], ... }`，每个小时对象已包含
  `uncached / cacheRead / output / reasoning / totalTokens / hitRatio / byType`
  （见 `lib/aggregate.js` 的 `hourlySeries` + `publicBucket`）。
- 前端需把该对象按日期升序拍平成一维数组，元素带 `day` 字段用于 x 轴标签。
- `loadAllData` 中：`< 3 天` 时请求小时序列；`≥ 3 天` 时不再请求（保持现有省流行为）。
- 注意现有 `state.hourly = hourly.hourly || []` 在「不传 day」时拿到的是对象，
  必须改为扁平化处理，避免 `.map` 报错。

验收：

- 今天（单日）：输入构成 24 个堆叠柱。
- 周一「本周」（2 天）：输入构成 48 个堆叠柱，x 轴能区分两个日期。
- 本周 3 天及以上 / 本月 / 本年：输入构成按天。
- 点击放大弹窗的输入构成与卡内粒度一致。

### C. 设置齿轮图标

现状：`assets/panel.js` 中 `#settingsBtn` 用字符 `⚙`，`assets/panel.css` 里
`.icon-btn { min-width:34px; padding-inline:8px; font-size:16px; }`。

目标：齿轮视觉大小与刷新按钮对齐（建议 `font-size` 提升到 20px 左右，
或改用 16–18px 描边 SVG 图标）。仅视觉调整，不改交互。

验收：齿轮与刷新按钮在头部同一视觉重量，不溢出、不挤压布局。

### D. 去掉 P50 / P95

`renderHero` 的 `hms` 数组中删除 `["P50 耗时", ...]` 与 `["P95 耗时", ...]` 两项。
**保留**「平均每轮耗时」。后端 `latency` 字段不动，只是前端不展示。

验收：hero 指标区不再出现 P50/P95。

## 版本与缓存

- `manifest.json` / `package.json` / `routes/ui.js` 的 `UI_CACHE_VERSION` 同步升到 `0.5.5`。
- 所有内部相对 import 的 `?v=` 同步改为 `0.5.5`（版本一致性测试会强制校验）。
- 原因：本轮改了 `assets/panel.js` / `assets/panel.css`，必须 bump `UI_CACHE_VERSION`
  才能让 Hana 重新加载静态资源。

## 不做什么

- 不改后端聚合口径、接口路径与返回结构。
- 不改 widget。
- 不新增第三方依赖。
- 不重构 `barChart` / `lineChart` / `stackedBars` 的底层实现。

## 测试要求

- 更新受影响的静态断言（如 hero 指标文案）。
- 新增断言：
  - hero 不含 `P50` / `P95`。
  - 单日隐藏每日趋势卡、显示小时 Token 趋势卡。
  - 输入构成粒度按 <3 天 / ≥3 天切换。
  - 小时序列扁平化处理（对象输入不报错）。
